# tabarena -- NOT installable via `pip install raman-bench[benchmark]` or
# `[models]`. PyPI forbids direct-URL requirements in an uploaded package (the
# v2.0.0 release attempt failed the upload with exactly this error), so the
# pinned-commit `tabarena` dependency has to live here instead of
# pyproject.toml, same reasoning as requirements-models-git.txt.
#
# Pinned to a specific upstream commit (not floating on `main`) rather than
# PyPI's `tabarena` release: the conda env deployed on HTW was found stuck on
# the old 0.0.1 PyPI placeholder (cluster/refresh_deps.py only ever upgrades
# raman-data, never tabarena), and even a healthy PyPI install would still be
# capped at 0.1.0 (cut 2026-09-03) -- missing mitra_v2, causilo, tabldm,
# ctboost, aplr, and every other model TabArena has merged since. Bump this
# SHA deliberately (not automatically -- see refresh_deps.py) when picking up
# new upstream models; a benchmark run's results should always be traceable
# to one exact commit, never a floating branch head.
#
# Install after `pip install raman-bench[benchmark]` (or `[models]`/`[full]`):
#     pip install -r requirements-tabarena-git.txt
#
# `[models]` needs the extras-qualified form (tabicl, ebm, search_spaces,
# realmlp, tabdpt, tabm, perpetualboosting, chimeraboost, nori) -- installing
# this after `raman-bench[models]` satisfies both `[benchmark]` and
# `[models]`'s tabarena requirement in one shot, since pip treats these as the
# same package with a superset of extras.
#
# `nori` was missing here until 2026-09-20 -- confirmed as a real production
# failure: NORI's large partition failed 237/654 tasks (36%), NORI's full
# partition was failing every task reached so far, all with
# "ModuleNotFoundError: No module named 'synthefy_nori'" (tabarena's own
# `nori` extra is `synthefy-nori>=0.10.0`, never installed here).
#
# Points at mario-koddenbrock/tabarena (a personal fork), not autogluon/tabarena
# directly, as of 2026-09-28: the previous pin (d06f406, on a since-deleted
# benchmark/rerun-new-pipeline-16092026 branch) had diverged from autogluon/
# tabarena's main (27 commits ahead, 23 behind -- confirmed via the GitHub
# compare API), so bumping straight to main to pick up one fix would have
# silently dropped or reordered unrelated work. Instead: branched off the
# exact previous pin and cherry-picked just the one commit needed
# (3db69f9 = d06f406 + upstream 8b08bf2 verbatim, "TabSwift: fix batched
# regression inference", autogluon/tabarena#620 fixing #618) -- confirmed live
# on the cluster: every TabSwift attempt at a small dataset (<~14 rows after
# CV split, e.g. microgel_synthesis) failed with exactly the tensor-shape
# RuntimeError this fixes. Only the vendored TabSwift file changed; every
# other model is untouched from the previous pin.
